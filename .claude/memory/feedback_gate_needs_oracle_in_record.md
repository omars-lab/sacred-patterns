Before authoring a validation gate that compares a verdict to a truth label, verify TWO premises against the codebase, not against the task text: (1) the value being gated actually appears in the per-construction record the gate's consumer reads, and (2) the truth label being compared against actually exists in the corpus. If either is false, ship the *authorable subset* (e.g. a coverage/presence test asserting only what's checkable) and file the missing oracle as a producer-side prerequisite — never invent a truth label to satisfy the literal gate spec.

**Why:** qiyas#301 asked to add F3 arrangement-classifier gates G5/G6/M3 to `calibration/i1/acceptance.yaml` ("verdict present / verdict == truth / macro accuracy"). Both premises were false: F3 (`classify_arrangement`) is invoked only by the separate `qiyas hint` command, NOT by `validate_detector.score_construction` (the only consumer of `acceptance.yaml`), so a gate would be dead config reading a verdict that isn't in the record; and scanning all 110 `pattern.gt.json` + 92 `corpus.json` entries showed NO arrangement truth label anywhere ("arrangement" substring absent; `symmetry` carries only `dominant_fold/rotational_orders`). Authoring G6 anyway would have meant tuning F3's expected output to whatever it currently emits (Tenet 7). Decided 2026-05-29: docs/decisions/2026-05-29-f3-i1-gate-scope-no-truth-oracle.md (Option B) — shipped a corpus-wide F3 *coverage* test (`tests/test_identity_hint.py::test_f3_emits_well_formed_hints_for_every_corpus_construction`), filed the verdict-vs-truth bar as conditional task #668 blocked on a producer-side label. Same shape as the F2 #302/#661 decision (cross-construction matching needs its own oracle, not a borrowed within-construction one) — see [[feedback_validate_label_descriptor_alignment_before_gating]].

**How to apply:** when a task says "add a gate G that checks X == truth" in qiyas (or any cascade), first `grep` the gate consumer's record builder for X (is the value even produced?) and scan the corpus fixtures for the truth field (does the oracle exist?). If a verdict lives in a *different* command's output than the gate's consumer reads, wiring it in is a prerequisite cascade, not a gate-add. If no truth label exists, building/emitting one (producer-side, Tenet 23) is the prerequisite — gate only after it lands. Surface the authorable subset now; defer the rest with a trigger-gated task.

**Side finding (detector-coverage, not F3):** the raster encoder (`encode_image(..., primitives_source="raster")`) returns ZERO shapes on 4 i1-corpus renders — `FALSIFIED-square-and-diagonal-line`, `petal-N-ring-0e6e3fa6`, `scalene-and-lens-shared-edge`, `scalene-chiral-pair`. F3 correctly emits no hints when there's nothing to classify; the zero is a raster-detection gap, distinct from F3. The coverage test tolerates these as a surfaced set (Tenet 3) rather than failing — but if raster-encoder recall is the topic of a future task, these 4 are the witnesses.
