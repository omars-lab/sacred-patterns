When designing a calibration-corpus entry that needs to witness source_primitives **cross-reference multiplicity** at the 3+ primitive level (e.g., three triangles fanned around a shared vertex, each pair sharing an edge), do NOT pick a construction where all primitives have the same `sides` count and use `classify .name where sides == N` to distinguish them — bikar's classify-by-predicate mechanism tags each face with **all matching class names** (not a unique one), so three triangles all matching `sides == 3` end up classed as `tri_a tri_b tri_c` simultaneously, collapsing into one detector class with face_count=N.

**Why:** Falsified 2026-05-26 (qiyas#132 Tick 9 triple-junction-shared-edge entry — three scalene triangles fanned around C0.cpt0 with verified geometry and 3 distinct triangle faces extracted by bikar). Render produced 5 shapes instead of expected 7; SVG inspection showed `class="tri_pab tri_pbc tri_pca"` on every triangle face. The classify-by-predicate semantic is "first-match-wins for style precedence, but ALL matching predicates attach as class names." Source: bikar's polygon-classifier walks each classify rule independently; faces don't carry "I came from polygon P_i" provenance accessible to the predicate parser.

**How to apply:** Before authoring a 3+ primitive Tier 1 entry whose intent is to witness cross-reference multiplicity in source_primitives, ask: "are my primitives heterogeneous in some predicate-visible attribute (sides, fill_color, layer index)?" If not, the witness is unrepresentable in current bikar DSL — either (a) defer the entry behind the DSL extension that adds `where source_primitive == "..."` predicates (gated through bikar Universal DSL Tagging cascade #495 path-expansion), or (b) pick a different compositional dimension that uses already-distinguishable primitives (e.g., tri+quad+pent at the 3-primitive level, where shared-vertex zero-cross-refs is already witnessable via triple-junction-shared-vertex and shared-edge cross-refs is already witnessable at the 2-primitive level across heterogeneous classes). Cross-class cross-references at 3+ primitive level ARE witnessable today; same-class cross-references at 3+ primitive level are blocked.

**Companion to:** [[feedback_consumer_audit_construction_contracts]] (the cascade designer must audit not just downstream consumers but upstream DSL expressibility — does the producer language even let me express the witness I want?), [[feedback_check_emit_layer_before_option]] (same shape: check the DSL emit/predicate surface BEFORE authoring a complex new corpus entry that depends on a missing predicate).

**Reinforced 2026-05-26 — Tick 15 chiral-pair falsification:** the same DSL gap blocks the chiral-pair witness (two scalene triangles with mirror winding, both sides==3). The "no classify, rely on source_primitives multiset via distinct polygon names" workaround was untested: gt-emitter requires a classify rule to emit a face into gt.json shapes; un-classified faces are walked into Brep but not into the shape array the matcher consumes. Tick 15's render produced only the 2 circle shapes, zero triangle shapes — falsified at premise, before even reaching the chirality-detector probe step. **The rule "same-class cross-refs at 3+ primitive level are blocked" generalizes to "ANY witness that requires two same-`sides`/same-`outward_arcs` faces to be distinct classes is blocked"** — chirality, polygon-twin cross-refs, mirror-symmetry absorption probes all fall under this. Until DSL extension lands (#495 Slice 4 trigger), pivot all such witnesses to heterogeneous-primitive geometries.
