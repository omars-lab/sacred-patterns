When a retrieval/re-identification/clustering metric scores far below a proposed gate, do NOT assume the descriptor (distance, signature, embedding) is broken and do NOT tune the metric or lower the gate to fit. First check whether the ground-truth **label** mixes classes the descriptor is structurally incapable of merging. A benchmark label that groups geometrically-distinct kinds caps retrieval below 1.0 *by construction*, independent of descriptor quality. The confirming move: re-score the SAME descriptor under a label at the descriptor's own granularity — if it jumps to ~1.0, the descriptor is sound and the answer key was wrong.

**Why:** qiyas#661 (2026-05-29), F2 cross-construction retrieval. First real-corpus run scored mAP=0.6067 / CMC@1=0.4551 against `face_class` — far below the #302-proposed F2-G1 (0.90) / F2-G2 (0.95) gates. The naive read is "the v1c signature distance is bad, widen the tolerance / drop the gate." The truth: `face_class` is a *fill/role* label (paint), not a *shape-identity* label. 14 of 37 classes span multiple vertex counts (`.hexagon` → {3,5,6,7,8,10}, `.royal` → {4,8,12,20}). Since `signature_distance` returns `inf` across differing vertex counts, a query labelled `.hexagon` has relevant-set members it is *structurally incapable* of ranking — the ceiling is bounded below 1.0 by the label, not the metric. Scoring the identical signatures under the detector's geometric `type` label (circle/lens/square/triangle/pentagon/decagon) gave mAP=1.0000 / CMC@1=1.0000. The descriptor was correct all along. This is the literature's **Cluster-Label Matching (CLM)** problem class (arxiv 2503.01097): external metrics are unreliable until ground-truth/descriptor alignment is validated.

**How to apply:** When any retrieval/clustering/re-ID metric misses a gate by a wide margin, BEFORE drafting tune/widen/lower-gate options: (1) inspect the label's intra-class spread along the descriptor's discriminating axis (here: vertex_count) — if one label spans values the descriptor treats as `inf`-distant, the label is the suspect; (2) re-score under an alternate label at the descriptor's granularity to confirm/exonerate the descriptor; (3) only then choose between relabel-the-ground-truth vs accept-the-label-and-report-as-noise vs emit-an-authoritative-label-from-the-producer (Tenet 23). The gate value itself is then label-dependent and should NOT be hardcoded until the label decision is made — defer it to the owner.
